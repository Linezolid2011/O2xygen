# O₂xygen 架构决策档案 (ADRs)

每条决定一条记录：**背景 → 决定 → 后果**。被否决的替代方案一并存档，防止返工。
新决定追加在末尾，已接受的决定如需推翻，追加"废止/修订"说明而不删除原文。

---

## ADR-0001 干净室重建原则:参照,不复刻
- **背景**:好友的「ORBIT」(世界观构造工作台) 闭源拒绝开源,我们以其成品为指引重建。
- **决定**:以他的公开输出(截图、口述、显示数值)为**参照系**做干净室重建;
  不复刻其代码/资源/版本,接受功能近似而非逐位一致。
- **后果**:验收标准是"复现其公开数值到合理容差"(如 Múspellsheimr 半径 0.008%、
  恒星 MIST 输出 <2‰),而非二进制等价。法律与道义上无瑕疵。

## ADR-0002 独立定名 O₂xygen,自 0.0.0 起独立演进
- **背景**:产品逐渐成熟,继续借用"ORBIT"代号不合适。
- **决定**:定名 O₂xygen(徽标 O 下标 2,字标 "xygen" 上标);首个自冠名版本 0.0.0,
  立 CHANGELOG。代码中对 "ORBIT" 的引用仅限描述参照对象的事实性注释。
- **后果**:品牌、包名(o2xygen)、目录名、FastAPI title 全部统一;RECON 笔记转入
  项目 docs/,作为历史档案保存。

## ADR-0003 版本号单一来源:docs/version.txt
- **背景**:版本号散落于 pyproject、服务端、页脚,推版时要改多处,易漏。
- **决定**:`docs/version.txt` 为唯一真源;pyproject 用 `dynamic = ["version"]`
  (setuptools file 读取),服务端启动时读取并经 `/api/system` 下发,前端页脚运行时渲染。
- **后果**:推版只需改一行;新增展示位必须从 API 读,禁止硬编码。
- **注意**:`version.txt` 必须无 BOM(Windows PowerShell 5.1 的 `Set-Content
  -Encoding UTF8` 会写入 BOM,setuptools 读入后版本号非法)。用无 BOM UTF-8 写入。

## ADR-0004 物理内核使用 Python
- **背景**:用户偏好 Python;MIST/ExoMol/气候求解生态以 Python/Fortran 为主。
- **决定**:物理内核为 Python 包 `o2xygen`(src 布局,numpy/scipy);允许安装任意
  依赖,PyPI 一律走清华镜像;下载数据落 D 盘。
- **后果**:性能敏感处(未来 Clima 求解器)可局部换 Rust/PyO3 或 numba,需新 ADR。

## ADR-0005 前端:无构建 ES modules + Three.js + uPlot
- **背景**:需要 WebUI;"做就做好",但引入 Vite/React 构建链在本环境(网络受限、
  无 npm 可达源)风险高。
- **决定**:手写原生 ES modules + importmap;Three.js(本地 vendor)+ uPlot;
  无构建步骤,刷新即生效。
- **否决**:React+Vite(构建链依赖 npm,registry 不可达)、Streamlit(用户明确否)。
- **后果**:代码量可控、故障面小;未来若上 React 需重写前端,届时立新 ADR。

## ADR-0006 后端:FastAPI 单体,同域静态托管
- **背景**:前端需要物理计算(辐照、结构、温度表、MIST)。
- **决定**:FastAPI 单进程;`/api/*` JSON API + `StaticFiles` 托管 web/;前端
  Kepler 传播仅作可视化层,服务端为真理来源。
- **后果**:无 CORS 问题;未来实时进度(Clima)用 SSE,需新 ADR。

## ADR-0007 MIST 插值:轨道空间双线性(否决 2D Delaunay 散点插值)
- **背景**:需要在 (初始质量, [Fe/H], 年龄) 上求恒星半径/光度/温度/风损。
- **决定**:每条轨道内对 log10(age) 做一维插值,再跨初始质量做一维插值,
  [Fe/H] 线性混合;轨道节点处精确。
- **否决**:scipy LinearNDInterpolator 直接对 (M, log age) 散点三角剖分——
  相邻轨道间三角形跨越巨大年龄差,太阳在 4.56 Gyr 处半径被扭曲到 +7%(实测)。
- **后果**:全部恒星标定向量通过;插值器接口 `MistGrid.evaluate(m, feh, age)`
  成为唯一入口。

## ADR-0008 恒星风损率取 |star_mdot|
- **背景**:MESA 的 `star_mdot` 是 dM/dt,主序风损期间为**负值**(实测约 −9.5e-14)。
- **决定**:损失率一律输出正值 |mdot|,插值前对每轨道取绝对值再 log 插值。
- **后果**:与参照应用显示的"当前损失率 1.146e-13"同量级同号;累计损失 =
  初始质量 − 当前质量(非 mdot×年龄,与参照应用口径一致)。

## ADR-0009 平衡温度体制:默认昼侧平均(T⁴ = S(1−A)/2σ)
- **背景**:参照卫星 Αύρα 显示 861.46 W/m² ↔ 288.238 K,对应 fast-rotator
  单位下因子 1.817,裸快旋无法解释(需 (1−A)>1)。
- **决定**:默认采用昼侧平均体制、反照率 0.09;同时保留全球平均/星下点两体制
  可切换;灰温室作为乘性因子保留在接口中。
- **后果**:UI 默认"昼侧平均";若后续截图证据修正(如含灰大气 gh≈0.82),只改
  默认值,不动接口。

## ADR-0010 不做程序化星空背景
- **背景**:常规做法是 Points 星野;用户已有一个可给定太阳系相对位置渲染真实
  星空的项目。
- **决定**:3D 场景背景留纯黑,不做任何程序化星野;未来与用户的真实全天球
  渲染器集成(相机姿态接口已预留)。
- **否决**:自建 ShaderMaterial 星野(已实现又删除)。
- **后果**:默认视图较空,可接受;集成点 = scene 背景 + camera quaternion。

## ADR-0011 3D 显示半径采用层级约束
- **背景**:纯按类型缩放会让巨行星的显示球比其卫星轨道还大(卫星"在行星内部
  运行"的视觉事故,用户截图指出)。
- **决定**:显示半径 = min(类型基线, 0.45 × 子女轨道近日点, 0.55 × 母球显示半径,
  0.3 AU 绝对上限);行星环外缘限制在子女轨道内侧。
- **后果**:任何"自定义成分近轨道卫星"的系统都不会再出现球吞轨道;缩放下小
  天体可拾取性靠标签/目录兜底。

## ADR-0012 UI 迭代采用无头 Chrome 截图驱动
- **背景**:"做完自己调",但本环境没有显示输出。
- **决定**:Playwright 驱动本机 Chrome(`channel="chrome"`),`scripts/shot.py`
  截图 + console/pageerror 捕获 + 点击等待辅助;沙盒内须将 TMP/TEMP 重定向到
  D 盘(playwright 需要可写临时目录)。
- **后果**:多轮视觉迭代成为标准流程;截图存档于 shots/,回归排查可复现。

## ADR-0013 资源版本用新不用旧
- **背景**:参照应用锁定 MIST v1.2 等旧版资源。
- **决定**(用户裁定):无兼容性问题时一律用最新可获取版本;截图数值仅作带
  容差的标定参照,不作精确验收。
- **后果**:MIST v2.5 网格列入候选;测试断言必须带容差并注明参照来源。

## ADR-0014 大文件下载策略
- **背景**:本机国际出口约 5 KB/s 且并发连接被服务器断流(per-IP 节流);
  MIST 网格约 107 MB/金属度。
- **决定**:优先找镜像/替代源(zenodo、npmmirror、fastly.jsdelivr);单流续传
  兜底;超大文件可由用户人工下载后放入约定目录(D:\test3\data)。
- **否决**:多连接 range 并行(实测聚合 0 KB/s,被节流)。
- **后果**:数据获取不阻塞开发;导入代码须容忍"数据未就位"(测试 skip)。

## ADR-0015 轨道传播:实时 N-body 积分,取代解析开普勒(用户裁定)
- **背景**:解析开普勒的上限就是参照应用当前的样子;继续跟随无法超越其 3 个月的先发优势,且对方随时可能开源。长期价值必须来自他做不到的东西——尤其是与 MIST 恒星演化的耦合。
- **决定**:传播真理改为**实时数值积分**(rebound 后端)。`kepler.py` 保留,职责缩窄为:初始状态构造(根数→状态向量)、二体标定真值、快速估算。显示用的轨道根数(半长轴/偏心率/周期)变为**瞬时根数**(由状态向量对母体换算,UI 注明 osculating)。恒星质量损失(MIST star_mdot)以绝热方式在步间更新质量(位置速度不变),长期时间轴上轨道真实膨胀(a ∝ 1/M)——解析架构无法表达的物理。
- **实测特征**:二体 50 yr 跟踪 <1e-5;1000 圈能量漂移 <1e-6;检查点恢复一致到 ~1 cm;同路径逐位一致。
- **修订(2026-11-14 晚):默认积分器 IAS15,WHFast 降级为可选项。** 实测:(a) IAS15 回扫 1000 yr 后 epoch 瞬时根数逐位恢复,WHFast 百年量级有 ~10% 级路径差;(b) IAS15 对本系统快 4 倍;(c) rebound 5 的 WHFast 质量变更须走 `sim.ri_whfast.recalculate_coordinates_this_timestep`(0.1.3 修复,旧代码写错字段名,静默无效)。**旗舰发现**:白玫瑰卫星瞬时偏心率数十年内 0.15 → ~0.10(Kozai 型循环),常量质量对照证实为真实动力学。
- **后果**:时间轴拖动需要检查点快照(fixed-dt + 快照存档,保持决定性与时间对称);前端 `kepler.js` 降级为服务端快照之间的渲染传播层;温度表管线改为沿积分路径采样;测试基准从逐位相等变为:二体收敛 + 绝热膨胀标定 + 能量漂移有界。
- **否决**:混合"解析+摄动修正"(复杂度接近全积分但通用性差);自研积分器为主(rebound 是 C 实现且 pip 可装,clean-room 不受影响——积分器是公共科学工具,非对方专有逻辑);仅保留开普勒(现状,天花板过低)。

## ADR-0016 世界即存档:扁平天体 + 笛卡尔初始条件 + 原点/时间原点(用户裁定,破坏性)
- **背景**:要支持多世界;层级(恒星/行星/卫星)与轨道根数作为内部状态表达限制了通用性(双行星互绕、无中心天体等无法表达)。
- **决定**:每个世界是 `[worldname].oxygen`(JSON,带 format/version)存档。内容:原点天体名;时间原点(t=0 语义,显示为 "yyyy-mm-dd From origin",均匀历 365.25 天/年,纯显示约定);每个天体的 初始质量/位置/速度(笛卡尔,SI);类型仅 恒星/非恒星 两种;恒星额外存 初始质量/初始半径/[Fe/H]/初始年龄(MIST 种子),非恒星额外存 反照率/半径。层级与"卫星"身份删除。
- **后果**:kepler 根数降级为"放置工具"(UI 输入根数 → 换算 p/v 存入存档);瞬时根数改相对**原点天体**计算(卫星相对恒星呈带摆动类行星根数——扁平化的诚实代价,也是 N-body 差异化特性);渲染坐标 = 绝对坐标 − 原点天体坐标;测试大量重写;0.0.1 之前无存档,无需迁移。
- **否决**:保留层级+根数内部表达、存档只存快照(无法表达非层级系统);世界存数据库(文件即存档最简单可 diff)。

## ADR-0017 显示尺寸 = 物理尺寸,drawn-to-scale(用户裁定)
- **背景**:非恒星显示基线(0.012 AU 量级)让"卫星轨道画进行星球"的视觉事故反复出现(ADR-0011 的层级钳制在 ADR-0016 扁平化时丢失,2026-11-15 再发)。判定:预设的物理轨道(0.01 AU = 0.27 r_Hill)完全合法,是显示尺寸与物理尺寸脱钩造成的。
- **决定**:渲染球半径 = body.radius_m(物理半径),无放大、无基线、无钳制。恒星在系统尺度下缩为亮点、行星为点——接受。配套可用性补丁(均非尺寸声明):不可见拾取代理球(真实球太小点不中)、恒星光晕小下限(发光≠大小)、相机近平面自适应(允许贴近行星)。ADR-0011 废止。
- **后果**:小天体在系统视角不可见,靠标签/目录/拾取代理定位;"轨道吞进行星球"类视觉 bug 从根上消失(球不再大于轨道)。
- **否决**:显示缩放带下限(下限迟早再次吃掉近轨);分层缩放(每体一个系数,心智负担与失真并存)。

## ADR-0018 推演 = 不可逆演化 + 存档自动改写 + 时间轴两态(用户裁定)
- **背景**:有了世界存档(ADR-0016)后,"时间如何流动"必须重新定义。
  可自由拖动的时间轴与"世界状态即存档"互相矛盾:回溯拖动到的状态
  无法表达为存档。
- **决定**:时间**只**通过推演流动。推演按 时长/速度 设置,积分器把
  世界向前推进,**每 0.5 秒墙钟把当前状态写回存档本身**(pos0/vel0 前移,
  恒星 age0 按经过年数推进);正确备份逻辑变为推演前"另存为"。时间轴
  两态:非推演模式完全惰性(刻度 NaN、播放键死);推演模式显示真实标度
  与进度(不可拖动),播放键 = 暂停/恢复,暂停时"推演"按钮变红担任
  取消(确认后彻底取消,回退到上次自动存档)。控制规则:时长开始后不可改,
  暂停随时允许,取消/调速仅暂停后(服务端 409 强制)。渲染平滑由
  服务器快照锚定 + 客户端同源传播补帧保证(债额 pacing 使服务器速率
  = 配置值;对时纠偏逐帧渗流、单帧上限自适应)。
- **后果**:查询语义必须非破坏化(温度类采样在恢复快照副本上进行,
  任何查询不得拨动活时钟);任务循环检测外部时钟移动并响亮中止;
  推演区间不存档检查点(不可逆,回溯无意义)。
- **否决**:推演后手动导出存档(把备份责任放在事后,违背"世界即存档"
  的直觉);保留可拖动时间轴 + 推演双模式(两种时间语义并存,必然
  desync)。

## ADR-0019 查询一律非破坏 + 取消即回滚 + 元数据进存档(2026-11-16 审计)
- **背景**:0.1.2 全面审计发现四处语义漏洞互相咬合:(a) `state_at(t_days=…)`
  显式时刻查询仍拨动活时钟(ADR-0018 只非破坏化了温度采样);(b) 取消推演只
  停表不回滚,与 UI 承诺的"回退到上次自动存档"矛盾,内存/磁盘分叉;
  (c) 存档序列化丢弃全部 `extra` 自由元数据(cmf/环/大气),现网存档已被
  洗没;(d) preset 未置零总动量,世界随时间线性漂移(旧存档原点星已在
  ~93 AU 外)。
- **决定**:(a) 一切查询(含显式时刻)在检查点恢复副本上求值,活时钟只由
  推演任务与 `Workspace.advance_to`(测试/工具专用)驱动;(b) 取消 = 停表 +
  等线程落地 + 从存档重建 Workspace,UI 在推演完成后整页重载以新 epoch 为准;
  (c) schema v1 增加 `extra` 透传,加载时 schema 字段权威于 extra 内的陈旧
  副本;(d) preset 建世界时统一扣除质心速度(伽利略变换,相对状态不变),
  旧存档由 `scripts/repair_world.py` 一次性修复(补 extra + 置零漂移)。
- **后果**:外部时钟移动检测器变为纯防御(正常路径不再有触发源);检查点
  归档的粒子数固定,推演中禁止添加天体(409),非推演期添加后归档重置。

## ADR-0020 运行期依赖最小化:标准库 HTTP 层,手写数值小件(2026-11-16,用户裁定)
- **背景**:venv 里 51 个 PyPI 包,其中 FastAPI 全家桶(fastapi/starlette/
  pydantic/pydantic-core[Rust 轮子]/uvicorn/anyio…约 20 个)只为 16 个简单
  JSON 端点服务;scipy 只被调用了 2 次(brentq、minimize_scalar);psutil
  可选;plotly/pyarrow/requests 等从未被 import。
- **决定**:(a) HTTP 层重写为标准库 `http.server`(ThreadingHTTPServer,
  HTTP/1.1 keep-alive),API 契约逐字节保持不变(紧凑 JSON 分隔符、
  {"detail"} 错误体、状态码语义);(b) `src/o2xygen/optimize.py` 手写
  Brent 求根与黄金分割有界极小化,取代 scipy 的两个调用点;(c) psutil
  用 ctypes psapi(GetProcessMemoryInfo)取代;(d) 卸载全部未被 import 的包。
- **否决**:替换 rebound(自研积分器可行但牺牲 IAS15 的精度/可逆性与
  10–100 倍性能,且 numpy 随 rebound 绑定,收益仅是"零依赖"的名义)。
- **后果**:运行期 PyPI 依赖 = **numpy + rebound 两个**;开发期 = pytest
  (+其自身依赖)与 playwright。51 → 12 个包。全部 69 项测试与 Playwright
  深烟测在精简后环境通过。keep-alive 断开属常态,BaseServer.handle_error
  不再向 stderr 倾倒 ConnectionAbortedError 堆栈。

## ADR-0022 参考系统一:rest-质心,根星概念退役(2026-11-17,用户裁定)
- **背景**:Εἴδωλον(1.2 M☉ 白矮星)加入后,Vesper 双星对(2.05 M☉)质量
  反超 Αστραία(1.29 M☉),"选谁当根星"成为无正确答案的武断题——一切
  质量接近的多星系统的通病。ADR-0016 已把 origin 降级为纯显示锚点,
  但锚点仍是"一个天体",这是未完成的去层级化。
- **决定**:**统一**参考系(否决双模):瞬时根数对每个天体相对**除自己以外
  的系统质心**计算,μ = G·M_tot;渲染与烟迹参考系 = 全系统质心。
  origin 字段退役为元数据(存档 schema 兼容:null 或命名天体均可读,
  但不再驱动物理视图);添加天体默认参考 = 最大质量天体;目录 ◎ 标记与
  "原点天体"面板文案删除。白玫瑰存档 origin 手改为 null。

## ADR-0023 自转与潮汐:恒定时间滞后的 secular 算子分裂(2026-11-17)
- **背景**:此前自转只是 `rotation_period_s` 的静态显示参数;潮汐完全不存在。
  要把自转轴、角速度与潮汐演化纳入同一套 N-body 真理,同时不能在高阶
  IAS15 的每个子步里调用 Python 力回调(性能不可接受),也不引入
  REBOUNDx 依赖(ADR-0020)。
- **决定**:
  1. 每个天体的权威自转状态为 `spin_axis`(惯性系单位矢量)、
     `spin_rate_rad_s`(非负角速率,转向由轴承担)、`spin_phase_rad`;
     `rotation_period_s` 仅是派生显示缓存,不再写入存档。
  2. 采用小滞后平衡潮模型:对宿主 i 与点质量扰动体 j,
     `w = (r̂ × v_rel)/r`,`C = 3 G m_j² k2_i R_i⁵ / r⁶`,
     垂直于 r 的自转分量以 `exp(-C Δt_lag Δt / I_i)` 向 w 松弛;
     平行分量在该近似下不变。固定几何下这是精确且任意步长稳定的更新。
  3. 自转角动量变化以相反符号施加到该二体对的轨道角动量:
     对相对速度作切向冲量,按质量反比分配绝对速度增量。总角动量
     (自转+轨道)严格守恒,总线动量不变;能量不被强制守恒(潮汐耗散)。
  4. 在现有演化节奏点与 MIST 质量更新一起施加,活积分器与温度采样副本
     都走同一路径。参数:`extra.love_k2`、`extra.tidal_dt_s`、
     `extra.inertia_factor`(默认 n=1 多方球 2/3−4/π²)。
- **范围限制**:不含潮汐撕裂、洛希极限、双星传质、潮汐加热发光;
  径向滞后与高分阶引力项未建模。靠近到宿主半径以内的轨道不属于本模型
  的适用范围。
- **附带修复**:演化节奏循环过去可能跳过短跨度的终点(短于 1 年时
  完全不应用 cadence 更新);现在终点总是被处理。
- **验证**:解析方向测试(快自转→减速、轨道角动量增加)、总角动量与
  总线动量守恒、存档轴/速率/相位往返;白玫瑰 20 年实测自转减慢并
  正确自动存档/重载。

## ADR-0021 服务器驱动渲染:SSE 推流,客户端零物理(2026-11-16,用户裁定)
- **背景**:"客户端传播 + 服务器纠偏"是全项目历史上 bug 密度最高的范式:
  双时钟(renderDays/clockOffset/bleed)、双积分(客户端 velocity-Verlet +
  服务器 IAS15)、EMA 速率估计、烟雾历史重采样——每个都量产过严重且隐蔽
  难复现的缺陷(0.5 秒跳帧、尾部跳变、desync 事故)。其存在根源是"推一次
  半秒"的旧传输开销;0.1.3 非破坏化 + 0.1.4 标准库 HTTP 层之后,loopback
  取位姿已是亚毫秒级,客户端传播失去存在理由。
- **决定**:**服务器是唯一计算机。** 新增 `GET /api/stream`(SSE,标准库
  手写,无协议栈):`pose` 事件(时钟变化即推,~60 Hz,含服务器仿真时刻
  与全天体绝对坐标)、`trails` 事件(~5.5 Hz,服务器回扫积分的烟雾路径,
  缓存未变不发)、5 秒心跳。客户端:删除 NBodyPropagator、渲染时钟、
  纠偏渗流、烟雾历史机器;渲染循环只画最新服务器位姿,烟雾头部顶点
  钉在最新位姿上(纯几何拼接,非物理)。800 ms 轮询保留:meta(恒星显示
  属性)与 SSE 失效时的降级通道。瞬时根数等读数仍走既有端点。
- **否决**:WebSocket(手写 RFC6455 分帧/掩码是为消灭隐蔽 bug 而引入新的
  隐蔽 bug 面;SSE 单向推流恰好匹配,且浏览器 EventSource 自带重连);
  客户端自攒轨迹历史(高速推演下 60 Hz 采样对短窗口只剩 ~3 点,物理上
  不成立——烟雾必须在服务器侧用检查点回扫);纯插值无推流(高速时采样间
  卫星转数百圈,插值无意义)。
- **后果**:暂停 = 服务器停推(逐帧精确冻结);取消/世界切换 = 推流自动
  重锚(emitter 每拍读全局 WS);客户端净删除约 300 行 bug 高发代码。
  实测(2026-11-16):2000 d/s 推演 72 s 流 ~178 KB/s、RSS 恒定、
  pose 实测 ~50–60 Hz、trails ~4–6 Hz;Playwright 烟测零页面错误。
- **ADR-0034 修订(2026-11-22,用户裁定)**:服务器唯一计算的是物理位姿;
  烟迹不再由服务器反算。当初否决客户端历史是为了短窗口顺滑,现在用户
  明确选择“放弃高速短周期烟迹顺滑度,也不能卡服务器/客户端”,并为
  CCSN 删除反向积分假设。详见 ADR-0034。

## ADR-0030 开放天体系 + 逃逸风账本 = 封闭守恒系统(2026-11-21,用户裁定)
- **背景**:ADR-0015 在步间只改质量、保持位置/速度,适合绝热各向同性风,
  但多星差异风损会改变**剩余天体**的 M/P/L/Q。ADR-0022 的“零总动量则
  质心惯性不动”只适用于质量固定的封闭天体系;根星退役后,这个历史缺口
  不再被显示参考系掩盖。用户裁定:守恒对象是**剩余天体＋逃逸风**,接受
  剩余天体自身不守恒,禁止用任意反冲或反复置零伪装成物理修复。
- **决定**:
  1. 新增唯一聚合风账本 `WindLedger(t_s,M,P,L,Q)`,全部使用 SI;L 相对
     **固定世界原点**,不是瞬时质心。恒星损失 dm>0 时,在改质量前记
     `dM=dm,dP=dm*v,dL=dm*(r×v),dQ=dm*r`;天体位置/速度不变,风不参与
     引力、rest-质心根数、渲染或烟迹。
  2. 风事件之间按无相互作用弹道传播 `Q(t+dt)=Q+P*dt`,M/P/L 不变;
     多次脉冲必须先推进旧风再添加新风。于是天体＋风的 M/P/L 守恒,
     `Qdot=P`;总动量为零时完整质心固定,否则匀速运动。物理风更新若
     增质量则响亮拒绝,绝不记录“负风”。
  3. 检查点快照携带同刻风账本;未来查询和温度采样携带私有副本;过去
     查询从检查点账本向前重放。自动存档/另存为将同一时刻的 M/P/L/Q
     写入 schema v2,只把账本运行时刻 rebase 为 0,不重复传播 Q;v1
     旧档缺省零账本。取消推演通过既有存档重建自然恢复上次风账本。
  4. 初始/迟到 MIST settle 是把种子质量同步到 epoch 当前质量,**不是
     新风事件**且不同步重建检查点会产生旧质量,故非记账并重置检查点。
     人工编辑/添加天体是新的初始条件:清空风账本,以统一平移和伽利略
     变换令 Q=P=0,保持全部相对位置/速度,重建检查点;跨人工编辑不要求
     旧守恒量连续。
  5. 总角动量定义为**轨道＋自转＋风**。MIST 不提供自转演化,采用明确的
     无力矩闭合:结构更新保持每颗恒星 `I*omega`,质量/半径变化相应调整
     自转;各向同性风只携带上述平动角动量,不附加自转力矩。潮汐仍在
     自转与轨道间交换角动量,不再被误判为守恒破坏。
- **边界**:不含风的双星传质/吸积、各向异性反冲、风对天体的后作用、辐射
  角动量或内部较差自转;逃逸风仅是守恒会计,不是额外引力粒子。过去查询
  仍沿用 ADR-0023 的现有限制:自转未做历史归档。
- **验证**:非零总动量/固定原点角动量、多星差异风损、连续风脉冲、弹道 Q、
  未来查询非破坏、两次存档重载、潮汐＋结构总角动量、人工增质量重置均
  有自动测试;总测试数 100。

## ADR-0031 编辑模式“对齐”:纯平移剩余天体质心到固定原点(2026-11-21,用户裁定)
- **背景**:右上角“一键计算”已是 legacy;世界坐标原点与剩余天体质心
  在风损后可以不同,需要一个显式、可确认的对齐工具,但不能复用
  ADR-0030 的人工编辑重置(那会加速并清空风,超出本操作语义)。
- **决定**:
  1. 顶栏以“对齐”取代“一键计算”。查看模式按钮灰色且原生 disabled,
     点击无反应;编辑模式为橙色。点击后打开与推演一致的应用内确认浮窗
     (dev11 起,不再使用浏览器原生 confirm),成功才覆盖当前存档并重新载入;
     取消/✕ 不发送请求,推演中服务端返回 409。
  2. 对齐只执行 `r_i' = r_i - R_b`,其中 `R_b` 是当前**剩余天体**质心。
     质量、年龄、速度、相对位置、相对速度、自转轴/速率/相位、时间、
     天文坐标与风的质量/动量均不变;不做速度归零,不清空风账本。
  3. 逃逸风不是额外平移的粒子,但其原点相关量必须按同一坐标变换:
     `Q_w' = Q_w - M_w R_b`,`L_w' = L_w - R_b × P_w`。天体与风始终处在
     同一个坐标系;轨道/自转/总角动量中依赖原点的部分按数学定义变化,
     这不是物理状态被修改。
  4. 对齐后旧检查点废弃,从当前对齐状态重建;WHFast 坐标同步刷新,
     客户端随重载清空烟迹(ADR-0034)。`origin` 元数据与 ICRS 天文定位不变。
- **验证**:非零风下位置/速度/质量/自转逐项不变、风 Q/L 坐标变换、
  确认后存档质心为零、未确认不写盘、推演冲突、查看/编辑按钮状态与
  确认取消/接受浏览器路径;总测试数 102。

## ADR-0032 Múspellsheimr 三合星外轨道与 Σκιά(2026-11-22,用户裁定)
- **背景**:纯 N 体对照证明 Múspellsheimr 初始 7.83 AU 绕 Αστραία 轨道
  会自然散射;不能靠“对齐”或把它硬拉回同一不稳定初值。用户要求保留
  Múspellsheimr 并改为绕三合星共同质心运行,同时在 Εἴδωλον 的 0.01 AU
  近距轨道增加一颗潮汐锁定行星。
- **决定**:
  1. Múspellsheimr 采用 300 AU 顺行圆轨道,参考为 Αστραία＋Vesper＋
     Εἴδωλον 的质心,轨道面由外层三星瞬时角动量确定;周期约 2842 年。
     其近日点远高于外层三星活动范围,避免重新落入 S 型强散射区,并
     尽量减弱对 Νεφέλη 的扰动。
  2. 新行星命名 **Σκιά**(“影”):半径 2,440 km、平均密度 5.5 g/cm³,
     由 `M=4πR³ρ/3` 得质量 3.3467307789e23 kg(约 0.05604 M⊕)。
     采用与 Vesper–Εἴδωλον 内双星同面的 0.01 AU 顺行圆轨道,初始
     `spin_rate=n`,公转/自转周期均约 7.9914 h;后续由实际潮汐模型演化,
     不将锁定状态写成永久固定输出。
  3. 轨道面由当前内/外层角动量构造正交基,既有天体的相对状态不变;
     人工轨道手术建立新守恒基线,统一平移/加速令 Q=P=0、清空旧风账本。
     候选与正式写入分离,正式覆盖前保留时间戳备份。
  4. Σκιά 的流体洛希极限约 0.00767 AU,0.01 AU 为其 1.30 倍,仍在极限外;
     Εἴδωλον Hill 半径约 1.74 AU。其近距轨道要求更小的 IAS15 基础步长,
     属于必要的解析成本,不得为提速而解析化客户端轨道。
- **验证**:完整七体真实风＋真实潮汐 100 年:Σκιά 最大 e=3.47e-6,
  自转/公转比 0.99999913,封闭守恒误差约 1e-16。长期对照先经实际
  生命周期 settle 到 WD 当前质量 1.203 M☉,禁止把 6.0 M☉ progenitor seed
  当成动力学当前质量。100 kyr 大尺度对照无 e>1 事件:Múspellsheimr
  最终 a=300.77 AU、e=0.0102,全程最大 e=0.0232、最大 r=301.45 AU;
  Νεφέλη、外层三星和内双星均保持束缚,总机械能误差 7.95e-15。

## ADR-0034 烟迹改为纯客户端权威位姿历史(2026-11-22,用户裁定)
- **背景**:ADR-0021 曾为避免高速采样混叠而让服务器反向积分烟迹。实际
  Σκιά 的 0.01 AU 轨道周期约 0.333 d,30 d/s 时每秒约 90 圈,60 Hz
  位姿根本不够顺滑;反算还在 Workspace 锁内消耗 CPU并阻塞位姿/推演。
  用户明确裁定:**放弃这种场景的烟迹顺滑度,但不得再卡服务器/客户端**。
  未来 CCSN 作为极端风损事件,也使“从当前状态反推过去”失去普适性。
- **决定**:
  1. 服务器只计算并推送权威 `pose`;删除 `_trails`、反向积分、烟迹窗口、
     时钟速率估计、`_trail_cache`、SSE `trails` 事件及 `/api/state` 的
     trails 字段。任何显示请求不得再为烟迹复制/推进 N-body。
  2. 客户端为每个天体保留最近 **240 个**实际收到的位姿。dev14 初版逐样本
     保存 `p_i(t)-R_b(t)`;ADR-0035 起改存**绝对世界坐标** `p_i(t)`,质心
     不再影响旧点。环形历史与 GPU position/color typed arrays 一次预分配;
     仅新增位姿时更新 geometry,不再每帧拼接或重建。
  3. 初始/刷新无烟迹,之后随真实采样生长;暂停或相同时刻不追加;时间
     回退/取消与 SSE 重连清空;世界切换的既有 reload 自然清空。不写入
     存档、localStorage 或其他持久层。
  4. 客户端只做采样点连线与渐变,不做插值、外推或物理积分。高速短周期
     下允许欠采样、折线和混叠,**不保证轨道形状**;增加容量不能替代采样率。
  5. 该历史是“实际收到的位姿”,不是完整积分历史;CCSN 可直接沿用,无需
     跨极端风损事件反推。若未来必须保留高速轨道形状,只能增加正向遥测
     采样,不得恢复显示专用反向积分。
- **验证**:102 项自动测试通过;隔离七体真实 MIST/潮汐场景将 Σκιά 恢复为
  0.01 AU(周期 0.332976 d,IAS15 基础 dt=0.0005933 d),30 d/s 实测 API
  p95=39.08 ms、帧间隔 median/p95=33.3/33.4 ms(约 30 fps);暂停稳定、
  取消/刷新清空、状态无 trails、页面与 HTTP 错误均为零。正式存档未改。

## ADR-0035 显示与绘图统一使用固定世界原点(2026-11-22,用户裁定)
- **背景**:ADR-0022 曾把渲染与烟迹绑定到剩余天体质心;但差异风损、
  人工质量修改、添加/删除天体和 CCSN 都会移动质心,导致整个画面与旧
  烟迹被重新平移。用户裁定:显示/绘图以**整体固定原点**为准,质心只
  作为诊断与“对齐”操作目标。
- **决定**:
  1. Three.js 天体、恒星灯、标签投影所用的 group、网格与客户端烟迹
     一律使用绝对世界坐标 `p_i`;`O=(0,0,0)` 固定,不随质量/成员/CCSN
     改变。选中聚焦和相机跟随仍相对天体工作,不限制用户平移/缩放。
  2. SSE `pose` 删除 `bcm`,客户端删除 `_bcmOf` 与所有 `p-bcm` 显示/
     历史变换。固定容量烟迹直接记录绝对位置,旧历史不被质心移动改写。
  3. `/api/sky` 观测者改用 `world_to_icrs_pc(frame,p_body,t)`;
     `astro_frame.position_j2000_pc` 固定锚定世界原点 O,不是质心。
     天空 pass 仍继承相机朝向而不继承相机位置,避免假视差。
  4. **瞬时轨道根数不变**:仍相对除自身外的系统质心并使用 `G*M_tot`;
     守恒诊断仍分别报告剩余天体与天体＋风质心。“对齐”仍是显式纯平移
     操作,但不再存在一个每帧自动跟随质心的隐藏变换。
- **后果**:质心剧烈移动不再使画面参考系跳变;旧存档若坐标远离 O,
  用户可聚焦天体或显式“对齐”,服务器不得自动重置其位置。
- **验证**:103 项测试通过;单天体绝对偏移的 ICRS 观测者回归、浏览器
  天体/灯光/网格/烟迹绝对坐标、pose 无 bcm 均实测;页面与 HTTP 错误为零。
